# CS619 Prototype Phase & Final Viva Guidelines

**Intended Readers:** All students who are registered in a new project in Spring 2026.

---

## 📌 Part 1: Prototype Phase

### What is the Prototype Phase?
The **CS619 project team** has taken additional measures to help students improve their software programming skills. The Prototype phase carries marks and is a critical stage in your project. A student must complete and submit it within the due date and clear the Prototype phase viva. A student may or may not be allowed to proceed further based on the flow provided by the department.

In case a student is not allowed to proceed further after the Prototype Phase, such student will be given another chance after completion of 2 semesters in the project. Then, such student can take the CS619 course in the 3rd semester starting from the current semester, as per CS619 policy. Also, such student shall keep working on all remaining parts of the project on their own so that time can be saved in the 3rd semester.

The learning material for the Prototype phase will be provided by the respective project supervisor. For this purpose, students must contact their supervisor well ahead of the starting date of the Prototype Phase so that students can learn the required programming skills before attempting the Prototype Phase.

The problem statement file for the Prototype Phase will be updated on the mentioned start date of the Prototype Phase under the **CS619 Assignments** section on VULMS. If it is not there, the student should immediately contact the project supervisor.

---

## 📤 Submission Procedure

1. **Submission Files:** Students must attempt and submit their complete folder (Code, Database, and any other files related to the Prototype Phase solution).
2. **Development Tools:** Students will use the development tools specified for their project, consulting with their project supervisor as needed.
3. **Platform:** Students must submit the solution file within the due date on **VULMS**. No submission after the due date will be accepted.
4. **File Size Limit:** Make sure the uploaded file size is **less than 50 MB**.
5. **Group Projects:** In case of two group members, Viva will be conducted on an individual basis, but the submission file shall be submitted by only one member.

---

## ⚠️ Important Deadline & Submission Policies

- **Strict Deadline:** There will be **no extended date**; the last date mentioned on VULMS will be final.
- **No Direct Email Submissions:** No submission via Email will be accepted unless a student faces a verified technical problem while uploading the file on VULMS.
- **Google Drive Backup Submission:** If a technical uploading problem occurs on VULMS, the student must upload the file within the due date to Google Drive and share the link via email with their project supervisor.
  - *Google Drive Help:* [https://support.google.com/drive/answer/2424384?hl=en](https://support.google.com/drive/answer/2424384?hl=en)
  - *Email Requirement:* You **must** use your official **VU student email ID** for any email communication.

---

## 🎧 Activities After Submission & Viva Setup

After the submission of the solution file, students will be scheduled for viva:

1. **Viva Scheduling:** Viva will be scheduled on a working day. Students can attend this viva from anywhere.
2. **Equipment & Connection Requirements:**
   - Active & reliable Internet Connection.
   - Video call support with screen sharing capabilities.
   - Working **Speakers/Headphones**, **Microphone**, and **Camera/Webcam**.
3. **Supervisor Contact:** Contact your respective project supervisor for details regarding Prototype Phase viva scheduling immediately after submitting on VULMS.
4. **Webcam Alternative:** If you do not have a dedicated webcam, you can use an Android Phone as a Web Cam:
   - *Android Webcam Setup:* [https://www.drivereasy.com/knowledge/use-android-phone-as-webcam/](https://www.drivereasy.com/knowledge/use-android-phone-as-webcam/)

## 🌐 Localhost Development Server Port Info

- **Frontend Application Port:** `http://localhost:8001`
- **Backend API Port:** `http://localhost:3000/api`

When testing the prototype locally:
1. Start the backend server on port `3000`.
2. Start the frontend application using `npm run dev`.
3. Open your browser and navigate to **`http://localhost:8001`**.
